# Capture Workflow

Use this workflow after meaningful engineering work.

## 1. Extract candidates

Ask what was learned that could change a future decision. Ignore routine edits, raw activity history, and information that is trivial to rediscover.

## 2. Search before writing

Search the knowledge index and relevant entries for the same underlying claim.

- If a canonical entry exists, strengthen it.
- If the new evidence contradicts it, record the contradiction.
- Create a new entry only when the claim is materially distinct.

## 3. Classify

Choose discovery, failure, decision, pattern, or rule. Default to the weakest justified classification.

## 4. Attach evidence

Create compact `EVID-*` records with stable references. Separate what was directly observed from what is inferred.

## 5. Evaluate promotion

Apply `promotion-policy.md`. Update observed projects, observation count, confidence, applicability, exceptions, relationships, and verification date only when evidence justifies the change.

## 6. Update project memory

If the work changes a project's reconnect state, update its memory checkpoint. Keep project memory concise and point to canonical knowledge rather than duplicating it.

## 7. Update indexes

Add or update the compact index record so future agents can discover the entry without loading its full contents.

## 8. Close with integrity checks

Before committing:

- no secrets or sensitive data
- no fabricated evidence
- no duplicate canonical entry
- no unsupported promotion
- no stale index pointer
- facts and inference clearly separated
